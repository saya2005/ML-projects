# База данных музыкального стриминга

Учебный SQL-проект команды **The Powerpuff Girls**. Мы спроектировали базу данных музыкального сервиса, которая хранит каталог треков, пользовательские плейлисты и историю прослушиваний.

[Скачать презентацию проекта (PDF, 20,6 МБ)](https://github.com/saya2005/ML-projects/raw/refs/heads/main/final.pdf)
## Какие вопросы решает проект

- Какие жанры лидируют по средней популярности треков?
- В какие часы пользователи чаще всего слушают музыку?
- Как хранить один трек в нескольких плейлистах и учитывать каждое повторное прослушивание?

## Как устроена база

Трек связан с альбомом и жанром, а альбом — с исполнителем. Таблица `Playlist_Track` связывает треки с плейлистами и хранит дату добавления. В `Listening_History` для каждого события записываются пользователь, трек и время прослушивания.

## Результаты проекта

- **Спроектировали базу музыкального сервиса.** Связали исполнителей, альбомы и треки. Для плейлистов предусмотрели связь «многие ко многим»: один трек может входить в несколько плейлистов. История прослушиваний хранит время каждого события, поэтому можно учитывать повторные прослушивания.
- **Подготовили запросы для анализа музыки и аудитории.** Один запрос ранжирует жанры по средней популярности треков, другой считает прослушивания по часам. Отдельно рассчитали число прослушиваний каждого жанра среди пользователей 18–25 лет.
- **Проверили, какой индекс выбирает база.** Для поиска истории пользователя за заданный период сравнили доступные индексы через `EXPLAIN`. В показанном плане база выбрала первичный ключ (`PRIMARY`), хотя среди возможных вариантов был и созданный индекс `idx_history_user_time`.
- **Продемонстрировали работу транзакций.** В первом сценарии создание пользователя и его плейлиста объединено в одну транзакцию с `COMMIT`. Во втором сценарии две тестовые записи пользователей откатываются одной командой `ROLLBACK`.
